# テスト方針

* 外部依存はDI(Dependency Injection)し、単体テスト可能とする
* 原則実装に対して単体試験コードを記述する

## 層の分け方

実機が要る部分と要らない部分を分け、要らない部分をすべてホストで検証する。

* `m5a-core` — ハードウェアに触れない。SDカードや通信は `ports` の
  トレイト越しに扱い、試験ではメモリ実装に差し替える
* `m5a` — 実機に触れる層。ここは実機で確かめる

## 実行方法

```sh
cargo test-core
```

`.cargo/config.toml` に定義した別名で、`cargo test -p m5a-core --target aarch64-apple-darwin`
を実行する。`build.target` が xtensa 固定のため、ホストのターゲットを明示する必要がある。

## 実機で確かめること

ホストでは代替できないため、書き込んで目視・実測する。顔の配置や色の規則は
`m5a-core` の試験で押さえてあるので、ここで見るのは「実際にそう見えるか」だけ。

* 電源投入後に画面が点き、顔が表示される
* まばたきと表情の切り替わりが滑らかに見える（画面全体が点滅しない）
* 画面に触れると座標がログに出る
* 画面右下のボタンを押している間だけ録音の表示になる
* SDカードに `/.m5a/config.toml` が作られる
* 記入済みの設定で起動すると設定不備の表示が消える
* 起動直後に設定画面（モジュールのステータス一覧）が出る
* WiFi未設定など不備があると、何が起きてどう直すかが英語で表示される
* 監視対象の全モジュールが揃うと自動的にアシスタント画面へ切り替わる
* 画面を左右にスワイプすると、設定画面とアシスタント画面を手動で切り替えられる
* 声の一覧をタップすると選択状態が変わり、`config.toml` の `voice` が書き換わる
* 設定画面の英語ラベルが崩れず読める（未確認。
  [設定画面の設計](design/settings.md#未解決の項目)を参照）
