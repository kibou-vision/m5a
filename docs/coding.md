# コーディング規約

## 命名規則

* 変数名は snake_case を使用する
* 定数は UPPER_SNAKE_CASE を使用する
* 関数名は snake_case で動詞から始める（例：get_user, validate_input）
* 型名（struct/enum/trait）は PascalCase を使用する

## 関数設計

* 関数は単一の責任を持つ
* 関数の引数は3個以下に保つ

## エラーハンドリング

* 回復可能なエラー（一時的と思われるエラーや、ユーザーによるエラー）は補足して、対処法をユーザーに示す。

## コメント

* コメントには実装を決定した理由を残す
* 何を実行しているかは、関数名や変数名など、コードで示す。コメントに記載しない。
* 修正の記録・過去の経緯をコメントに残さない
* コメントは簡潔に記述し最小限にする
