# 設計

* Rust での実装を第一候補とする。
* デバイスアクセス等、Rust での実装が存在しない場合は C言語 を利用する。

## 構成の考え方

実機でしか確かめられない部分と、机上で確かめられる部分を分ける。

* `m5a-core` — ハードウェアに触れないロジック。設定、状態遷移、ガードレール、
  Realtime プロトコル、音声変換、表情、描画。ホストで単体テストする
* `m5a` — 実機に触れる層。電源IC、画面、タッチ、SDカード、通信、音声。
  コア層が定めたトレイトを実装して差し込む

コア層は ESP-IDF に一切依存しない。これにより μ-law 変換や状態遷移のような
間違えやすい部分を、実機なしで網羅的に検証できる。
